# BeeCount · 安卓收支自动捕获

[English](README_EN.md)

基于 BeeCount 改造的个人记账项目，重点解决付款、收款后还要手动截图、录入的问题。新增通知监听、成功页面文字读取、可选本地截图 OCR 和本地待确认列表，先捕获收支信息，再由用户核对入账。

**定制源码位于 [`payment-auto-capture` 分支](https://github.com/jiaotuke/BeeCount/tree/payment-auto-capture)。** 仓库首页的 `main` 分支仅作说明入口，请切换到功能分支查看和构建本版本。

当前仅发布源码，不发布 APK 或应用商店版本。

## 我们增加了什么

| 新增内容 | 当前实现 |
| --- | --- |
| 首页待确认收支 | 首页月度收支下方显示待确认数量及最近两笔，点击记录直接核对分类、账户和金额；「查看全部」进入独立列表，不必经过权限设置。尊重首页金额隐藏设置，返回首页及前台停留时自动刷新。 |
| 收支通知监听 | 授权后读取微信、支付宝的付款与收款到账通知文字，分别提取候选支出和收入。 |
| 自动检测收钱 | 识别明确的「收款到账」「收款成功」「支付宝到账」等文字，以及明确显示「你已收款」的已收转账；普通到账提醒、待收款和收款码不推断为收入。 |
| 成功页面识别 | 通过安卓无障碍服务读取微信、支付宝付款成功和收款到账页面的可见文字，不依赖手动截图，不自动点击或操作支付。 |
| 本地截图 OCR 兜底 | 默认关闭，单独说明并同意后才启用。Android 11+，适配的微信转账收款及红包领取详情页可使用内置中文 OCR，不上传图片或识别文字，不保存截图。 |
| 微信红包收入 | 只处理已领取详情页，要求「已存入零钱」到账提示；按文字坐标取提示上方的本人金额，排除下方总额与其他领取者金额。首页标为「收入 · 微信红包」，金额不明确时仍需核对。 |
| 本地待确认列表 | 原生服务将捕获结果保存在本机，展示来源、时间、原文、金额和商户，供用户核对。 |
| 金额不明确时待核对 | 缺少金额或出现多个金额时保留候选记录，不自行猜测实付金额。 |
| 重复处理 | 区分收入与支出后按订单号或通知事件去重；短时间同应用、同金额、同方向的待确认记录标记可能重复，同金额收钱和付款不会互相去重。 |
| 确认入账 | 待确认列表区分收入和支出；收款进入收入分类，付款进入支出分类，核对金额、分类、账户后保存；保存后移除待确认记录，取消编辑则保留。 |
| 保存恢复处理 | 使用候选记录的固定标识关联交易，处理已保存但尚未移除候选记录的恢复场景，减少重复入账。 |
| 权限与开关 | 通知监听和页面识别分别控制，默认关闭；提供用途说明、系统授权入口和权限状态。 |
| 测试与构建检查 | 新增支付文字解析测试、页面交互测试，以及原生编译与 APK 检查脚本。 |

这些改动集中在安卓支付捕获流程；账本、账户、分类、统计和导入导出等基础结构沿用上游项目。

## 使用流程

1. 在功能分支构建并安装个人测试版，创建本地账本。
2. 打开 **我的 → 自动化 → 支付自动识别（试验版）**。
3. 按需开启「监听付款与收款通知」「识别付款成功与收款到账页面」，并在系统设置中授予相应权限。页面文字不可读时，可另行开启「本地截图文字识别兜底」，阅读用途说明后确认。
4. 完成付款或收到款项后，返回此页面刷新待确认列表，检查「待确认支出」或「待确认收入」。
5. 查看原文，核对金额、分类和账户，再确认入账；不需要或重复的记录可以忽略。

日常处理可直接使用首页的「待确认收支」卡片。卡片中的记录尚未计入账本；点击某一笔核对后保存，或点击「查看全部」集中处理。独立列表右上角齿轮可打开识别设置。

关闭应用内开关会停止相应处理，也可以在系统设置中撤销权限。

## 当前边界

- 当前实现为 **自动捕获、确认入账**，尚未实现无确认直接入账。
- 截图兜底仅允许适配的微信转账及已领取红包详情页面，聊天、付款密码、未拆红包、收款码和通用网页不在允许列表中；支付宝及其他付款成功页尚未适配截图兜底。系统禁止截图时停止，不绕过系统保护。
- 红包没有可读取的平台唯一 ID 时，仅能按页面窗口和 OCR 特征处理重复：同窗口同特征去重；重新打开后的相似记录提示疑似重复，不直接丢弃可能真实的另一笔同额红包。
- 当前针对微信、支付宝的人民币消费和明确收款；退款、充值、提现、还款、普通转账提示和未确认收款暂跳过。「你已收款」仍需用户判断是否属于收入，自己的账户互转应忽略。
- 支付应用没有发出通知、隐藏了通知内容，或页面文字无法被无障碍服务读取时，可能漏记。
- 缺少订单号时，跨来源记录不一定能可靠合并；相同金额也可能是两笔不同的真实消费，需要人工核对。
- 待确认列表最多保存 500 条，满后暂停接收并显示提示。处理记录后仍需核对暂停期间的原始账单。
- 后台捕获依赖安卓系统保持相关服务可用，锁屏、省电策略和系统停止服务都可能影响结果。

## 数据与隐私

通知和页面文字由本地规则解析；可选截图兜底使用随包提供的 ML Kit 中文 OCR，不调用云端大模型。截图只在内存处理后释放，不写相册；识别后的文字作为待确认记录保存在应用私有 SharedPreferences 中，并非额外加密的保险箱。

截图、通知原文及 OCR 输出不上传用于识别。ML Kit SDK 可能发送性能、使用统计和请求兼容信息，详见 [第三方声明](THIRD-PARTY-NOTICES.md)。关闭截图开关即停止截图兜底，关闭页面识别也会停止它。

确认后的交易沿用原项目的数据与同步逻辑；是否同步由用户的账本和云同步配置决定。

## 开发与构建

本次验证使用 Flutter 3.27.3、Dart 3.6.1、Java 17，以及 Android SDK 36 / Build Tools 35。

```bash
git clone --branch payment-auto-capture https://github.com/jiaotuke/BeeCount.git
cd BeeCount
flutter pub get
flutter run --flavor dev
```

本地构建 ARM64 调试包：

```bash
flutter build apk --flavor dev --debug --target-platform android-arm64
```

Windows 建议使用纯英文构建路径，避免 Flutter 原生着色器编译器的中文路径问题。下载工具链与依赖前，将 Flutter、Pub、Gradle 和 Android SDK 的目录或缓存配置到 D 盘项目目录。
