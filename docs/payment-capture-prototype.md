# 安卓收支自动捕获

入口：我的 → 自动化 → 支付自动识别（试验版）。

`0.2.3` 起首页月度统计下方直接展示「待确认收支」卡片：数量、最近两笔、金额待核对及疑似重复提示；点击单笔复用同一确认编辑器，查看全部进入不含权限开关的独立列表。首页金额隐藏同步作用于预览，回到首页/应用恢复前台及首页停留期间刷新；识别设置可从独立列表的齿轮进入。待确认记录仍不计入账本收支，保存后才计入。

## 已实现

- 通知访问服务：仅处理微信、支付宝，提取付款与收款文字。
- 明确的收款成功、收款到账、支付宝到账和「你已收款」进入待确认收入；付款成功进入待确认支出。收入确认页只展示收入分类，旧版本候选未带方向字段时仍按支出处理。
- 无障碍服务：读取这两个应用的页面文字，不点击或发起支付。文字不可读时，可单独开启指定页面的本地截图 OCR 兜底。
- 通知、页面文字和截图兜底均默认关闭。通知与页面需要系统授权；截图兜底另有明确用途说明及独立开关，必须先开启页面识别。
- 通知与页面文字使用本地规则；可选截图兜底用随包提供的 ML Kit 中文 OCR，不调用云端大模型。截图只在内存处理后释放，不写相册；候选文字保存在应用私有目录。SDK 性能与使用统计说明见第三方声明及开启对话框。
- 后台原生服务捕获，Flutter 未运行时也能保存；系统停止/强制停止服务、未授权或支付应用未提供文字时无法捕获。
- 同方向内按订单号和通知事件去重；短时间同金额同方向记录标记疑似重复，不以相同金额为由直接丢弃可能真实的第二笔。方向加入订单、事件和页面指纹，同金额的收入与支出不会互相去重；兼容旧支出事件索引。
- 自动捕获后，在待确认列表核对原文，进入原有编辑器选分类、账户，保存成功后移除候选。取消编辑保留候选。
- 多金额（含到账金额与手续费）或金额缺失保留待确认；退款、充值、提现、还款、未确认转账、二维码收款请求与普通余额到账提示不识别为收入。个人已收转账由用户判断是否应记收入，自己的账户互转应忽略。
- 待确认最多500条，达到容量时显示暂停提示，需人工核对期间账单；事件去重索引保存7天。

## 必须明确的边界

这是自动捕获、确认入账版本，不是付款后无确认直接入账版本。不能保证识别所有支付页面或通知。尚需真机确认通知格式、支付应用的无障碍文本、锁屏与后台存活行为。

同一笔跨来源且缺少订单号时只能提示疑似重复。原文不是经过支付平台认证的交易凭证。金额相同不代表同一笔交易。

截图兜底需要 Android 11+，当前只允许 `com.tencent.mm.plugin.remittance.ui.RemittanceDetailUI`（微信转账详情）。聊天、付款密码、收款码、通用网页和支付宝页面不在允许列表。原生窗口进入事件确定页面身份，截图前、截图后及识别回调均再次检查窗口、应用、开关和页面代次，离开页面或关闭开关后不保存结果。单次页面最多尝试三次，两次尝试至少间隔 2.5 秒；已捕获页面不连续截图。Android 14+ 直接截取指定窗口，系统拒绝截图时不绕过保护。

OCR 文本只对中文字符间空白，以及「你/您己收款」「你/您巳收款」中的状态词做纠正；不改金额数字。通知和原生文字不走这项 OCR 纠正。待确认列表仍展示识别原文，用户需要核对金额。测试版可通过显式 USB `dumpsys activity service ... --ocr-text` 查看内存中的上次 OCR 文字，用于排障；原文不写入 logcat，也不保留诊断截图。发布版禁用此文字诊断。

当前设置和提示采用中文，后续接入原项目多语言。原文保存在私有 SharedPreferences 中（不是额外加密的安全存储），应用数据备份策略与原项目一致。不要用真实账单截图或通知内容编写公开测试。

测试建议：微信、支付宝各完成一笔人民币消费与收款；测试双来源、同金额先收后付、优惠金额、连续同金额收款、到账金额与手续费、金额缺失、收款码、待收转账、对方已收款、退款、撤销权限、后台/重启与取消编辑。检查收钱只进入收入分类、付款只进入支出分类、每一笔只确认保存一次，不能凭模拟测试宣称真机兼容。

开发包使用 dev flavor，与官方 prod 应用分开安装。保留原作者和许可信息。本仓库许可证对修改版本公开源码有要求；公开发布前处理许可要求，未经用户指示不自动发布仓库或账目数据。

## 本机验证命令

`scripts/local-android.ps1 deps` 安装依赖；`analyze` 检查修改涉及的 Dart 页面；`test` 运行权限与待确认列表界面测试；`build` 尝试构建 dev/debug arm64 APK。

`scripts/verify-payment-native.ps1` 运行纯 Kotlin 收支解析、OCR 状态词纠正和页面允许列表测试，并针对 Android API 35 编译原生队列与通知核心。依赖 ML Kit 的截图读取与无障碍服务由完整 Android 构建编译检查，不再由单独 Kotlin 核心编译替代。

Flutter、Pub 和 Gradle 缓存放在本工作区的 D 盘 `.tools` 目录。Java 和 Android SDK 复用已有的 `D:/ai bazi/.tools` 工具链。构建脚本中的路径针对当前电脑，可在迁移时调整。
